# 公式適合性スイートの日次更新

[起動・実行手順](setup.md#公式適合性テストの実行)

`Update official conformance suite` は毎朝 **06:05 JST（21:05 UTC）** に公式リポジトリの
既定ブランチを確認します。毎時00分の負荷を避けるため5分に設定しています。
GitHub Actions のスケジュール実行には遅延があり、時刻は厳密な保証ではありません。
ワークフローを main にマージすると有効になります。Actions の Run workflow からも実行できます。

## 更新PRと検証

- 固定SHAは `scripts/conformance/upstream.json` だけで管理します。
  通常のCIも、更新PRの検証もこのSHAを使用します。
- 更新がなければ終了し、重い公式スイートの実行は行いません。
- 更新があれば `automation/conformance-suite` ブランチのPRを作成・更新します。
  既存ブランチには main をマージし、force-push は行いません。競合時は失敗させます。
- PR本文には上流の比較リンク、モジュール件数、追加・削除されたテスト名を記載します。
  上流でコメントアウトされているテストは有効化しません。
- 更新PRは自動マージしません。上流のアサーション・API・variantの変更も比較リンクで確認します。

追加のSecretは使いません。`GITHUB_TOKEN` が作ったPRでは通常のPRワークフローが起動しないため、
日次ワークフローから通常テストと再利用可能な公式CIを明示的に呼び出します。
公式CIはFederationのRS256・PS256・ES256の3方式と、OIDC Core Basicの事前登録クライアント構成を実行します。
実際に検証した候補コミットのSHAに **Scheduled conformance validation** チェックを登録し、
両方の検証が成功した場合だけ成功とします。スキップ・中断・失敗を成功にはしません。
詳細はチェックから日次ワークフローへ移動して確認できます。
ブランチ保護で必須チェックを指定している場合は、このチェック名との整合も確認してください。

書き込み権限はPR作成ジョブと結果報告ジョブだけに限定します。
上流のJavaソースをビルド・実行するジョブには読み取り権限のみを渡し、Git認証情報も残しません。

## GitHub側の設定

リポジトリの **Settings → Actions → General → Workflow permissions →
Allow GitHub Actions to create and approve pull requests** を有効にする必要があります。
このワークフロー自身はPRの承認やマージを行いません。
組織のポリシーで禁止されている場合は、その設定の調整が必要です。
設定不足の場合はPR作成ステップが失敗します。GitHub AppやPATへの暗黙の切り替えは行いません。

## テスト構成が変わった場合

更新処理は新しい件数を候補の `expectedModules` に記録しますが、確認済みテスト名の
`scripts/conformance/modules.json` と異常系の期待値を自動変更しません。
実行時に公式APIが返すテスト名を確認済みリストと照合するため、件数が同じでも
テストの入れ替わりは失敗になります。

追加・削除されたテストや新しい異常系の要求を確認し、必要なProvider実装と回帰テスト、
確認済みリスト、拒否応答の期待値を更新してから再検証してください。
Basicの確認済み構成は `scripts/conformance/basic.json` で固定し、追加・削除も実行時に検出します。
公式の REVIEW は引き続き人手確認待ちです。CI成功を全件PASSEDや認証取得とは扱いません。

上流のJavaアノテーションが動的な指定などに変わって解析できない場合は、安全側に失敗し、
固定SHAを更新しません。その場合は上流差分を確認して更新スクリプトを修正してください。
